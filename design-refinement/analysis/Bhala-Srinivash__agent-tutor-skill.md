# Analysis: Bhala-Srinivash/agent-tutor-skill

## 1. What it is
- A Claude skill (`/learn`) that runs a live tutor loop (Explain, Example, Check, Evaluate, Practice) over free-text learner answers, with per-concept mastery tracked under `~/.learn/` using an FSRS-style spaced repetition schedule.
- Includes a "zero-hint" quiz rulebook, a learner profile (style, confusion tolerance, analogy domain), a dashboard of proficiency badges, and prerequisite-check sequencing.
- Cites little formal research. It names Mia Kiraki's four "AI cognitive traps" (fluency illusion, zero retrieval practice, no desirable difficulty, forgetting architecture) and Bjork's "desirable difficulty". The FSRS file is a simplified approximation, and its difficulty-adjustment section corrects itself mid-text ("wait, this should boost easy concepts"), so treat the constants as unverified.

Files read: `SKILL.md`, `references/teaching-loop.md`, `quiz-rules.md`, `fsrs.md`, `templates.md`.

## 2. Transferable principles

- P1 Zero-hint option design: option labels are neutral, with no explanatory descriptions that leak correctness, no "(Recommended)", and the correct answer's position randomised. In LORE, labels are <= 12 words and carry no claims already, so add a lint for leaking qualifiers ("always", "only", "most") unique to the correct option. — source: `references/quiz-rules.md` § Zero-Hint Policy — evidence claimed: none cited (adapted from the RoundTable02 `tutor-skills` repo).
- P2 Distractors only an expert can eliminate: every wrong option is a real concept from the domain that represents a common misconception. LORE already requires this (pedagogy §3); the new element is the test "if a non-expert can eliminate it by elimination of form, rewrite it". — source: `references/quiz-rules.md` rule 5 — evidence claimed: none.
- P3 Rephrase, never repeat, when drilling a weak concept: a re-test of a missed idea asks it from a new angle, in a context the learner has not seen (the "400 vs 422" example: pick the status code for a new situation). Same as the delayed re-test rule. This repo adds the specific instruction to test the distinction, not the one answer. — source: `references/quiz-rules.md` § Drilling Weak Concepts — evidence claimed: none.
- P4 Never the same explanation twice: if explanation A did not land, B uses a different angle (analogy, simpler prerequisite, case). Already in LORE pedagogy §3. New element: before re-teaching, step down to a prerequisite probe to find where the confusion starts. In buttons: a "prerequisite check" branch after the second miss, with 1 probe on the prerequisite and routing by answer. — source: `references/teaching-loop.md` § EVALUATE and Anti-Patterns 6 — evidence claimed: none ("Bjork's desirable difficulty" named only).
- P5 Specific praise tied to the demonstrated step: feedback on a correct pick says exactly what the learner showed ("You separated the shunt direction from the saturation"), never "great!". Author writes a distinct correct-feedback line per correct option and per route, not one generic "Yes." — source: `references/teaching-loop.md` § EVALUATE "If they understood" — evidence claimed: none.
- P6 Concept-level mastery derived from path, not from score: each concept (objective) gets a status from its evidence. Translate the 5-badge scheme into deterministic path rules for the report: Unmeasured (not probed on this path), Weak (missed twice or needed the full explanation), Fair (correct after hint or retry), Good (correct first try but "Guessing"), Mastered (correct first try, "Sure", and correct again on the delayed re-test). — source: `SKILL.md` § Dashboard; `references/fsrs.md` § Status Badges — evidence claimed: none.
- P7 Prerequisite gating by diagnostic: do not teach a concept until its prerequisite is confirmed. In buttons: a retrieve-segment probe on the prerequisite with a branch to a short refresher if missed, rejoining the main line. LORE's retrieve segment already does this; make the refresher branch mandatory for every `prerequisite` listed in the blueprint. — source: `SKILL.md` § Sequencing Protocol — evidence claimed: none.
- P8 Rating from path evidence (an FSRS-lite): map a probe's outcome to Again/Hard/Good/Easy using only recorded path facts: wrong twice = Again, wrong then right or hint used = Hard, right first = Good, right first + Sure + fast-lane taken = Easy. Use it to set review-card order and intervals in the report, from a fixed table (no per-learner floating-point state needed, only a lookup). — source: `references/quiz-rules.md` § FSRS Rating After Quiz; `references/fsrs.md` Initial Parameters table — evidence claimed: FSRS (open-spaced-repetition); constants unverified.
- P9 Difficulty mix by purpose: a diagnostic set is 40/40/20 easy/medium/hard and a weak-area drill is 0/30/70. Port as a segment-level rule: a hook or retrieve probe set is mostly easy-medium, and a traps or consolidate set is mostly hard. — source: `references/quiz-rules.md` § Difficulty Balancing — evidence claimed: none.
- P10 Wrong is not stupid, struggle is not failure: tone rule for feedback on the second miss ("This one trips most people, and here is why it is tempting"). LORE's voice rules cover it. Add an explicit "second-miss line" per key probe. — source: `references/teaching-loop.md` Anti-Patterns 5 — evidence claimed: none.

## 3. Rejected

- "Explain it in your own words" and "I get it is not evidence": needs free text and a judge of understanding.
- Learner profile questionnaire (style, analogy domain) driving explanation style: learning-styles matching is unsupported by the evidence the repo cites, and per-learner generation needs runtime AI. A fixed pre-authored set of explanations cannot adapt to an arbitrary analogy domain.
- FSRS state updated per learner across sessions in `~/.learn/` files: needs persistent per-learner computation and a runtime agent. Only the lookup-table version (P8) transfers. The multiplier and retrievability formulas are also marked as approximate in the source.
- "Rate their recall" by the tutor on a free-text answer: runtime AI grading.
- Dashboard with proficiency badges over long time horizons (S >= 90 days "Mastered"): the app cannot observe 90-day retention. Use path-based badges only, labelled as such, never as retention claims.
- Source-aware teaching (PDF extraction, URL fetch): the factory already uses a verified claim bank.
- "Detect rapid-fire clicking and ask the learner to slow down" (teaching-loop.md): needs timing telemetry and free-form dialogue. A fixed pause node after N consecutive fast taps on probes could be pre-authored if the player exposes timing, but that is outside this brief.

## 4. Concrete changes for the LORE factory

| Principle | Where | Change |
|---|---|---|
| P1 | Validator | Lint: for each probe, flag a label that contains one of {always, never, only, all, none, most common, first-line} when it is the only label with such a word. Flag a probe where the correct label is the longest in more than 60% of module probes. Error for the first, warning for the second. |
| P2 | `reference/rubric.md` R2 | Add anchor line: "5 = a learner who knows the topic only superficially cannot eliminate options by form". Judges test by asking whether any distractor can be dismissed without the topic knowledge. |
| P3 | `reference/pedagogy.md` §3 | Add: the delayed re-test must test the distinction, in a new case (new presenting situation, not new numbers only). Validator: re-test node's `objectives` match the original and its text differs (also see P5 in the anything-to-course file). |
| P4 | `reference/techniques.md` new T14 "Step-down prerequisite" | Fits `mechanism, diagnosis, management`. Recipe: after a second miss, offer one probe on the simplest prerequisite of the idea; if right, return with a contrast explanation; if wrong, run the refresher node then rejoin. Validator: every key probe with a `retry` loop has a `help` or prerequisite branch (count). |
| P5 | `reference/pedagogy.md` §3 | Add: correct-feedback names the specific step shown, one line per correct route; "Yes." or "Correct." alone fails R8. Validator: flag feedback nodes whose first message is under 4 words. |
| P6 | Report rule | Per-objective status table in the report. Rules (each uses only the objective's probes): Unmeasured = no probe on this path; Weak = any probe missed twice or explanation node reached; Fair = correct after a hint or one retry; Good = correct first time, Guessing; Solid = correct first time, Sure, and correct again at the re-test. Show 1 line of pre-written advice per status per objective (author supplies 3 lines per objective in `blueprint.json`: `report_lines.weak|fair|good`). |
| P7 | Blueprint and validator | Blueprint lists `prerequisites` per segment. Validator: every listed prerequisite has a probe in a `retrieve` segment with a refresher branch that rejoins. |
| P8 | Report rule and module format | Add per-card `rating_from_path` rule table, deterministic: Again, Hard, Good, Easy as defined above. Report orders cards Again first, then Hard, then by `schedule_days`; interval multiplier is a fixed lookup in the report file, not computed per learner. Mark intervals as "suggested", not as a retention claim. |
| P9 | `reference/pedagogy.md` §5 | Add a difficulty profile per segment type (hook/retrieve easy-medium; clinical medium; traps hard). Judges check in R6. Not a validator item since difficulty is not countable. |
| P10 | `reference/techniques.md` T6 | On a second miss at a key probe, use a reassurance line from a fixed set ("Common trap, and here is why it pulls people in") before the second explanation. Validator: second-miss feedback nodes exist for each key probe (count nodes of `role: feedback` reached from a `retry` of a `retry`). |

## 5. Testable hypotheses

- H1: Modules whose report assigns per-objective status from path rules (P6) and gives a pre-written action line per status will score higher on the learner-advocate "is it actionable at 1 a.m." judgment than modules with a single overall score.
- H2: Key probes with a step-down prerequisite branch after the second miss (P4) will show a higher simulated-learner recovery rate (correct at re-test after two initial misses) than probes that go straight to a second explanation.
- H3: Segments authored with a second-miss reassurance line plus a second explanation by a different technique will score higher on R5 (adaptivity) and R8 (voice) than segments with a repeated explanation, blind-judged.
