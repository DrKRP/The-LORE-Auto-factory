# Analysis: umass-ml4ed/prompt_distractor_generation_NAACL

Note: the repo is code only (data is private, no results shipped). Findings below come from the prompts, data schema and evaluation code. I cite no paper numbers, because none are in the repo.

## 1. What it is
- Research code for "Exploring Automated Distractor Generation for Math MCQs via LLMs" (NAACL 2024 Findings). It generates 3 distractors, each with a feedback text, for a math MCQ, given question, solution and correct answer.
- Methods compared: kNN in-context examples (SBERT retrieval), zero-shot chain-of-thought (error-first or reasoning-steps-first), rule-based (pick from a misconception list), fine-tuning (GPT-3.5, Mistral), and sampling-based baselines.
- Evaluation is overlap with gold distractors that real students chose (Eedi data), plus a separate LLM ranker that predicts which of two distractors students pick more often.

## 2. Transferable principles

- P1 Distractor = (error, option, feedback) triple, authored together: In the trap brief, every distractor record carries a one-line conceptual error ("what the learner wrongly believes or does"), the option label, and its feedback node. A choice with `kind: misconception` is not allowed without all three. The dataset schema has per-distractor `misconception`, `option` and `explanation` fields, which is the same triple. — source: README.md (Data Format), PromptFactory.py `_disAllInfoErrorPrompt` — evidence claimed: none in repo; the repo's premise is that errors drive distractors.
- P2 Error first, then option: Author in this order: (1) state the error as a conceptual rule-break, (2) derive the option text that a learner holding that error would pick, (3) write feedback. Never invent the option and then justify it. The prompt template puts `Distractor1 Error:` before `Distractor1:`, so the error is generated first. — source: PromptFactory.py `_zeroShotAllInfoErrorPrompt`, `_disAllInfoErrorPrompt` — evidence claimed: none in repo.
- P3 Errors are conceptual, not item-specific: The error statement must not mention the numbers, names or findings of one vignette, so the same error can be reused across probes and traced in the report. The zero-shot prompt says "errors should be conceptual in nature and should not refer to numbers, variables, or names in the question". LORE equivalent: error text is stated at the level of the misconception (M-id), and the option text is the item-specific instance. — source: PromptFactory.py `_zeroShotAllInfoErrorPrompt` — evidence claimed: none.
- P4 Flawed-reasoning chain per distractor: For each distractor, write the 2-4 atomic steps a learner would take to reach it (the first wrong step marked). The prompt asks for "atomic" flawed reasoning steps ending in the distractor. In pre-authored form this becomes the "why it was tempting" half of feedback, with the first wrong step named, and it supplies the hint ladder (hint 1 points at the step, hint 2 names the rule). — source: PromptFactory.py `_disAllInfoReasoningPrompt`, `_zeroShotAllInfoReasoningPrompt` — evidence claimed: none (an ablation of reasoning vs error vs feedback prompts exists in the code; results are not in the repo).
- P5 Feedback is tied to the specific distractor, shown on selection: The data model stores `explanation` per distractor ("feedback to be displayed to the student as an explanation of why that is not the correct answer"). This confirms per-option feedback nodes, with no shared "incorrect" node. — source: PromptFactory.py `_zeroShotPrompt`, README.md — evidence claimed: none.
- P6 Retrieve similar solved items as exemplars (kNN) at authoring time: Use kNN for the authoring agent, not the learner. For a new segment, pull the most similar already-published segments (same misconception family or same subject) and show their trap and distractor and feedback triples as in-context examples to the author. The repo embeds question + explanation + answer and retrieves top-k by cosine similarity. It can exclude examples sharing a construct (`exclude_construct_level`) to test generalisation. — source: RetrieverFactory.py `KNNRetriever`, conf/main.yaml (`k: 3`, `encodingPattern: q+a+f`) — evidence claimed: none in repo.
- P7 Select from a curated error list, then write options: The rule-based approach gives the generator a list of known errors for the topic and asks it to "first select N most likely errors" before writing distractors. This maps to the LORE blueprint step: the architect picks the M-ids to cover from the primary brief, and authors are told to use only those errors. Candidate errors are pooled per topic (the construct level) from all prior distractors. — source: misconception_selection.py, PromptFactory.py `rule_based_selection_prompt` — evidence claimed: none.
- P8 Evaluate distractors against real learner choice proportion: Each gold distractor has `proportion` (share of students choosing it). Quality is defined as being picked by real students, not as sounding plausible. For LORE, record per distractor an expected-pick rank from PYQ analysis or simulated learners, and check the pre-authored options are not trivially dominated (one obvious wrong option). — source: README.md (`proportion`), utils.py `compute_ranking_pairs` — evidence claimed: none.
- P9 Three-way coverage metrics: relaxed (any gold hit), hard (all gold hit), proportional (fraction of gold hit). LORE analogue for the validator: per probe, the share of trap-brief errors that appear as options (hard = all, relaxed = any). — source: utils.py `relaxed_metric`, `hard_metric`, `proportional_metric`; evaluation.py — evidence claimed: none.
- P10 Pairwise preference test between options: A ranker is asked "which of two incorrect options are students more likely to pick?" with tie cutoffs, tested in both orders to remove position bias. LORE judges can run a blind pairwise "which wrong option is more tempting" check on the options of one probe, and flag probes where one option wins every pairing. — source: ranking_model.py (`get_task_prompt`, `compute_ranking_pairs` with `both_orders`, `tie_cutoff`) — evidence claimed: none in repo.
- P11 Dedupe and sanity-filter generated options: Candidates are dropped if they equal the correct answer or duplicate another option. Validator: no two choices in one probe with the same normalised label, no distractor label equal to the correct label. — source: utils.py `normalize_candidate_distractors`, `clean_string` — evidence claimed: none.
- P12 Pre-authored per-distractor diagnostic report (design implication): Because every distractor carries (error id, error text, reasoning steps, feedback), the end-of-module report can be assembled from the path: "You picked X for the case on Y: the underlying slip was <error>. Tempting because <step>. Correct reasoning: <claim-cited sentence>." The repo shows the data model to store for this, which is the same four fields per distractor. — source: PromptFactory.py (all error/reasoning/feedback templates) — evidence claimed: none.

## 3. Rejected
- Generating distractors at runtime with an LLM (the whole method): violates no-runtime-AI; usable only as an authoring aid.
- Fine-tuned GPT/Mistral and sampling-based baselines (`openai_finetune/`, `mistral_finetune/`): training a model has no role in a pre-authored app, and there is no data in the repo to adopt.
- LLM ranker as a live quality gate (ranking_model.py): runtime AI. Only usable offline as an extra judge in the factory.
- Free-text answer parsing via regex on `Distractor N:` lines (evaluation.py): a response-parsing concern for generated text, not relevant to buttons.
- Exact-string match to gold distractors as quality: for clinical content the same misconception has many surface forms; string overlap (after `clean_string`) is too strict. Use error-id match instead.
- Math-specific normalisation (`clean_string` LaTeX handling): domain-specific, irrelevant to medical MCQs.
- Misconception pooling by math construct hierarchy (construct1/2/3): no equivalent taxonomy; LORE uses the M-ids from the blueprint.

## 4. Concrete changes for the LORE factory

| Principle | Target | Change |
|---|---|---|
| P1, P3 | `reference/pedagogy.md` §3 | Add rule: "Each misconception M<n> in the blueprint has a one-line conceptual error statement with no case-specific numbers or findings. Every `misconception` choice is the item-specific instance of that error." |
| P1, P2 | blueprint format (module-architect), `reference/module-format.md` | Extend `misconceptions[]` entries: `{id, text, source, error, first_wrong_step}`. `error` is the conceptual rule-break; `first_wrong_step` is the earliest faulty inference. Authors derive option text from `error`. |
| P2, P4 | `reference/techniques.md` | Change T6 recipe: add "Name the error, then the first wrong step the learner takes, then refute." Add new T13 "Error-to-option derivation": the author drafts error, then the 2-4 flawed reasoning steps, then the option that results, then the feedback. Fits: traps, clinical, diagnosis, management. |
| P4 | `reference/pedagogy.md` §3 hint ladder | Specify: hint 1 points at the step where the reasoning goes wrong without naming the error; hint 2 states the governing rule with claims. Hints are derived from `first_wrong_step`. |
| P5, P12 | report rule | For each distractor chosen anywhere in the path, the report lists: probe stem (short), option picked, error text (from the M entry), the cited correct sentence, and whether the learner later passed the delayed re-test of that M. Group by M-id, not by node. Sort by confidence (confident errors first). |
| P12 | report rule | Path patterns: (a) same M-id chosen at 2+ probes -> "recurring misconception" section naming the error once; (b) chosen then passed the re-test -> "repaired"; (c) chosen, then failed re-test -> "still open", with the review card for it; (d) never selected, fast-laned past -> "not tested by a wrong tap; fast lane taken" (no claim of weakness). |
| P6 | factory skill, author stage | Before authoring a segment, inject up to 3 exemplar (error, option, feedback) triples from published modules or `variants` in the same subject, selected by simple retrieval over the M text. Keep as an author-prompt rule; do not let exemplars supply facts (facts only from the claim bank). |
| P7 | architect rule | The architect must choose M-ids from a candidate pool (`pattern.md` distractors + exam notes) and mark each blueprint M as `pool` or `invented`. Validator warns if more than half are `invented`. |
| P8, P10 | `reference/rubric.md` R2 | Add anchor at score 5: "options within a probe are comparably tempting; no option is dominated". Add a judge instruction for segment mode: run a blind pairwise "which wrong option would a tired student pick more" for each probe; probes where one option wins every pairing are listed in `flaws`. |
| P9 | `scripts/factory.py` validator | Add metrics: `error_coverage_relaxed` = share of probes with at least one misconception choice mapped to an M-id; `error_coverage_hard` = share of blueprint M-ids targeted by at least one choice (already a rule; report as a number). Count `distractors_per_probe` (target 2-3 of 3-4 choices). |
| P11 | `scripts/factory.py` validator | Errors: two choices in one node with identical normalised label; a `misconception` choice label identical to the `correct` label. Warning: a misconception feedback node with `claims: []`. |
| P1 | validator | Error if a `misconception` choice's `misconception` id is missing from the blueprint, or the M has an empty `error`. Warning if two M-ids share identical `error` text. |

## 5. Testable hypotheses
- H1: Segments authored with the error-to-option derivation (P2/P4, a new T13 or the changed T6) will score higher on R2 (misconception work) than the same segments authored without the explicit error and first-wrong-step fields, measured by blind judge scores on matched segments. Candidate experiment: author the same trap segment under T6-old and T6-new, 3 judge lenses.
- H2: Probes whose feedback names the first wrong step ("tempting because ...") and whose hint 1 points at that step will produce more repaired re-tests (re-test correct after an initial miss) in simulated learners than probes with generic hints. Measure: share of M-id re-tests passed after a first miss across the sim personas.
- H3: Probes in which no option is dominated (pairwise check passes) will show a more even spread of simulated-learner wrong taps across options, and a lower share of correct-by-elimination answers, than probes failing the check. Measure: entropy of tap distribution over wrong options per probe in sims; R2 and R1 scores.
- H4: Authoring with 3 retrieved exemplar (error, option, feedback) triples (P6) will raise R2 and lower G1 fidelity flags relative to authoring with no exemplars, when exemplars carry no facts. Measure: R2 mean and count of G1 gate failures per segment across a batch.

## Caveats
- The repo has no reported results, so no efficacy claim carries over. All hypotheses above are untested for LORE.
- The domain is middle-school math with numeric distractors, where an error maps to one computation slip. Clinical distractors often come from partial knowledge or look-alike diseases, so the "error then option" order may fit trap and contrast segments better than recall probes.
